# Decisions

Choices the spec leaves open, one line each, with the section they fill in.

- §13.8 `unicode-ident` is held at 1.0.24 in `Cargo.lock`, because `ra-ap-rustc_lexer` 0.178 refuses to build when it and `unicode-properties` disagree on the Unicode version.
- §17 CI runs on pushes to `main` only, and a newer push cancels the older run, so rapid merges do not queue macOS minutes.
- §17 The Actions workflow waits in `ci/workflows/ci.yml`: the gh token has no `workflow` scope, so `scripts/enable-ci.sh` (needs the user's browser sign-in) moves it into `.github/workflows/`. Until then `cargo xtask ci` runs the same steps locally before every merge.
- §13.2 `neomem-engine` may depend on `neomem-proto`, because `Engine::handle(Request) -> Response` takes the protocol's types.
- §13.2 Any crate may use `neomem-testkit` as a dev-dependency; runtime dependencies follow the §13.2 table, enforced by `cargo xtask check`.
- §17.4 Clippy pedantic runs without `missing_errors_doc`, `missing_panics_doc` and `must_use_candidate`: the first two demand doc comments, which the no-comments rule bans, and the third asks for an attribute on nearly every getter.
- §13.3 `Embedder::embed` takes a `Purpose` (query or document), because retrieval embedders such as EmbeddingGemma and Qwen3-Embedding use different prompts for each.
- §13.1 Spool files are removed once the daemon has handled them, and unreadable ones move to `spool/rejected/`; the spool is a transient queue, not memory. A crash between logging and removal can log a spooled add twice, which §2.4 already allows (no dedupe keys).
- §13.1 A write (`neomem add`) never starts the daemon: if neomemd is down it is spooled at once and drained on the next start; reads start the daemon and wait up to 2 s.
- §13.5 Proof scenarios run debug builds while other work shares the machine, so their timing claims are sanity bounds; the §13.5 budgets themselves are checked by `neomemctl bench` on release builds.
- §13.4 `neomem models test <role>` also takes `--source <name>` (checks a `[models.extractor_by_source]` override) and `--structured` (checks structured output), and reports when the first streamed text arrived.
- §13.4 `neomem login chatgpt` runs the sign-in in the daemon: the daemon binds the localhost callback, does PKCE, exchanges the code and writes `secrets.env`; the thin CLI only prints the address, opens the browser (`--no-browser` skips it) and waits up to 5 minutes, so it needs no HTTP client.
- §13.4 `neomem models test <role>` also takes `--input <text>` (repeatable): the embedder embeds the first input as a query and the rest as documents and reports each document's cosine to the query; the judge and checker take the first input as the context and score the rest as candidates.
- §17.2 `neomemctl up --models real` runs EmbeddingGemma-300m through llama.cpp and the live Jev API, and keeps the fake server for the LLM roles. `JEV_API_KEY` is read from `~/.neomem/secrets.env` into the daemon's environment only, never written into the isolated home. The home's `models/` links to the main checkout's gitignored `models/`, which `neomemctl fetch-models` fills from Hugging Face (sha256-checked, with a second repo as the mirror).
- §13.8 llama.cpp comes from `llama-cpp-2` 0.1.160 without its default features: no OpenMP (ggml's own thread pool was as fast here and needs no libgomp) and no `common` library. Metal is switched on for macOS by a target-specific dependency; x86_64 Linux builds with `-C target-cpu=x86-64-v3`, without which llama.cpp compiles for SSE2 only and embeds 1.7x slower.
- §13.4 Each local model runs on its own worker thread that owns the llama.cpp model and context; calls queue on it. Every layer goes to the GPU when the build has a GPU backend. Embedders pick prompts and pooling from the GGUF architecture: EmbeddingGemma uses `task: search result | query:` / `title: none | text:` with mean pooling, Qwen3-Embedding the retrieval instruction on queries with last-token pooling; texts are cut at 512 tokens and documents are embedded up to 32 per batch.
- §13.4 Every `Llm` adapter validates a structured answer against its schema (a JSON Schema subset: types, required, properties, closed objects, items, enum, anyOf) and retries once with the problem quoted; the validated JSON reaches `on_text` once, so a rejected answer never streams to the caller. Code fences around the JSON are dropped.
- §13.4 LLM roles without a `timeout` get 120 s.
- §13.4 Chat Completions sends `max_tokens` (what OpenAI-compatible servers accept) and effort as `reasoning_effort`, or `reasoning.effort` when the base URL is OpenRouter; OpenAI itself is reached with `api = "responses"`. A server that ignores `stream` and answers with one JSON body is read as such.
- §13.4 Anthropic effort goes to `output_config.effort` and thinking stays at the model's default (adaptive on current models); the system prompt carries `cache_control: ephemeral`; a request without a limit asks for 16,000 output tokens; thinking blocks never reach the text.
- §9.4 / §6.3 The nightly jobs run at `[schedule] nightly_at` (default 03:00, local time via `jiff`); `croner` is not needed for one fixed daily time.
- §17.2 `neomemctl set clock=…` works only on daemons started with `[dev] settable_clock = true` (written by neomemctl for isolated homes); the real daemon refuses it.
- §9.4 The drift check repairs by re-indexing the differing files, and rebuilds when an indexed memory has lost its file, so the index always follows the files.
- §13.4 The `command` provider writes `{model, effort, system, messages, response_schema, tools, max_output_tokens}` as JSON to the program's stdin; stdout is the answer, unless it is a JSON object with only `text` and `tool_calls`, which carries tool calls. It has no schema mode (structured requests also get the JSON-only prompt) and does not stream: the answer reaches `on_text` once, when the program exits.
- §13.4 The `codex` provider keeps one `codex app-server` (`cmd`, default `["codex", "app-server"]`) warm per role and runs each call as an ephemeral, read-only thread with approvals off, declining any request the server makes. The system prompt goes in as developer instructions (Codex keeps its own base prompt), several messages as a JSON transcript, effort as the turn's effort and a schema as `outputSchema`. App-server tools are not open to clients, so tools become an output schema (`text` plus `tool_calls`, each tool's arguments held to its own schema when that schema is strict). A failed call restarts the server on the next call.
- §13.7 Process adapters are tested against `neomem-fake-llm`, a testkit binary that speaks the command and codex app-server protocols and asks the fake model service's scripted LLM for each answer.
- §13.4 `neomem login chatgpt` uses the public OAuth client and `localhost:1455` callback that Codex, pi and Hermes use (the ChatGPT sign-in accepts no other), with PKCE (S256) and `originator=neomem`. The tokens it gets are neomem's own, kept in `secrets.env` as `NEOMEM_CHATGPT_ACCESS_TOKEN`, `_REFRESH_TOKEN`, `_ACCOUNT_ID` and `_EXPIRES_AT`; neomem never opens another app's auth file. A provider may set `issuer` and `callback_port` (tests use a fake issuer and port 0).
- §13.4 The `chatgpt` provider refreshes its token when it has under 5 minutes left, under a lock so only one rotation runs, and saves the rotated refresh token at once. It posts the Responses body to `{base_url}/responses` (default `https://chatgpt.com/backend-api/codex`) with `chatgpt-account-id`, `OpenAI-Beta: responses=experimental` and `originator: neomem`, sends the system prompt as `instructions` and no `max_output_tokens`.
- §13.4 `secrets.env` is written through a temporary file created with mode 600 and renamed into place; lines for other names are kept.
- §13.5 llama.cpp is compiled optimized even in dev builds (`[profile.dev.package.llama-cpp-sys-2] opt-level = 3`), because a Debug llama.cpp is about 30× slower and would make every debug proof misleading.
- §10.3 The offline judge is Qwen3-Reranker-0.6B (Q8_0 GGUF) rather than bge-reranker-v2-m3, because it takes an instruction: the judge's question is its Instruct, the context its Query (the last 768 tokens) and each candidate, or each option's meaning, a Document. P(yes) comes from the last token's yes/no logits, which works with any Qwen3-Reranker GGUF; the shared prompt is decoded once for up to 32 documents. `decide` normalizes the options' P(yes) to sum to 1.
- §10.3 `FallbackJudge` asks Jev first and hands that one call to the local reranker when Jev errors, is unreachable, or misses the role timeout (600 ms by default); with no key it goes straight to the reranker and names it as the model. Each hand-over is logged with the model names and the reason only. The reranker loads on its first call and one copy serves the judge and checker; `judge = { runtime = "llama.cpp", file = … }` uses it alone.
- §13.8 The GPU backend is a build switch: `neomemd`'s `vulkan` and `cuda` features (Metal is always on for macOS). `neomemctl` turns on CUDA when `nvidia-smi` and `nvcc` answer, Vulkan when `vulkaninfo`, `glslc` and the Vulkan headers are present (installing the SPIR-V headers into `~/.cache/neomem/` when the system lacks them), and the CPU otherwise; `NEOMEM_GPU=cpu|vulkan|cuda` overrides it. A plain `cargo build` stays CPU-only so CI and machines without a GPU toolchain build.
- §13.5 `neomemctl bench models` measures the local models on release builds; the numbers live in `docs/models.md`. EmbeddingGemma-300m stays the default embedder (3-7x faster than Qwen3-Embedding-0.6B here).
- Capture logs each transcript message or action envelope as a turn, drops raw tool result bodies, retains only result status, and uses byte offsets plus an atomic intake/position transaction; pi reads the persisted active ancestry and never retracts previously captured history after branching.
- Isolated real-model proofs accept live keys only from environment variables; the control CLI never reads the real ~/.neomem to discover credentials.
- Search, recall and model tests refresh idle timing; background worker model calls do not extend the read idle window.
- Model selectors accept a bare model on the current provider, a configured provider/model prefix, or a local .gguf filename for the embedder, judge and checker.
- index.db records active-model and staged-vector progress; model-history.json retains provider configurations, without secrets, so a restart can reopen the old embedder during a swap.
- Capture hooks bound stdin to 4 MiB and give input/delivery 20 ms internally, leaving headroom inside the 50 ms process budget; folder watches and the sweep recover missed signals.
- Pi branch reactivation checkpoints emitted transcript entry references together with intake records and byte positions, so previously skipped ancestors can be captured once when selected.
